# 本機語言學習工具實作計畫

版本：2026-10-22。專案暫名「拾語」，儲存庫 `lng-learn`。

本文件是後續 Codex 的施工依據。`P0` 為本次基本架構；`P1` 完成可日常使用的 MVP；`P2` 為後續擴充。除「目前狀態」明列完成的項目，其餘均為待實作。

## 1. 產品定義與假設

服務對象是在自己電腦上學習非母語的單一使用者。以口說輸入減少建卡負擔，結合釋義、音標、母語人士錄音、圖片、例句、常用片語與短故事，經使用者校閱後保存，再依回想結果安排複習。

- 本機 server + browser；無帳號、無多人協作、無公開部署、無同步。
- 首個完整 MVP：美式英語 `en-US` → 繁體中文釋義；結構預留多語，首版不宣稱支援所有語言。
- 桌機操作優先，窄螢幕可用，支援鍵盤與基本輔助技術。
- 建卡可連網；已保存卡片與排程不應依賴即時內容服務。
- 預設以「看到英文 → 回想意思」為單一卡型。反向產出卡、聽音辨義、克漏字留在 P2；不同卡型各有排程。
- 一張卡先對應一個明確詞義。不要一次塞入同一字的所有義項。
- 母語人士發音是可追溯的真人音檔；TTS 是可用的備援，但介面必須明確標示合成。
- 目標是降低建卡時間與長期遺忘；不承諾只靠單字卡即可掌握完整語言能力。

## 2. 學習依據與介面轉化

| 原則 | 如何轉成產品行為 | 驗證方式 |
| --- | --- | --- |
| 主動提取／回想 | 正面先只顯示提示，不自動揭示翻譯、圖片或例句答案；揭示後才能評分 | 翻卡前無評分按鈕、無自動播答案 |
| 分散練習／間隔複習 | FSRS 依卡片狀態、評分與經過時間決定 due，不用固定天數冒充個人化 | 注入時鐘測試狀態與到期佇列 |
| 正確回饋 | 揭示時提供確認過的詞義、發音與例句；辨識／生成後可人工校正 | 建卡一定經過預覽與確認 |
| 語境與多種提示 | 背面分層呈現例句、圖像、搭配詞、小故事，優先顯示必要內容 | 可折疊補充內容，使用者能刪除不相關素材 |
| 限制認知負擔 | 一卡一義，預設短例句與短故事；不同辨識能力用不同卡型 | 一眼可看到釋義與例句，不以內容多寡當成學習成果 |

研究依據：外語單字的重複提取可改善延後測驗的回想表現，支持將回想放在揭示答案之前。[Karpicke & Roediger, 2008](https://doi.org/10.1126/science.1152408)。分散練習研究顯示間隔與預期保留時間相關，不能假設一組固定間距適合所有情境。[Cepeda et al., 2006](https://pubmed.ncbi.nlm.nih.gov/16719566/)。

上述「圖片、語境與故事的呈現方式」是產品設計假設，需藉使用者測試與學習紀錄驗證，不宣稱圖片越多、故事越長就一定越有效。FSRS 是排程模型，不能取代內容品質與實際語言使用。

## 3. 核心使用流程

### 3.1 建立與補充單字庫

```mermaid
flowchart LR
  A[主頁／選擇單字庫] --> B[建立或開啟單字庫]
  B --> C[唸單字／拼字／文字輸入]
  C --> D[確認辨識文字]
  D --> E[選詞義與口音]
  E --> F[取得字典資料、素材與原創學習內容]
  F --> G[預覽並編輯]
  G --> H{確認儲存?}
  H -->|是| I[原子保存 Note、Card、Media 關聯]
  H -->|否| G
  I --> C
```

P0 先省略多詞義選擇與真實內容取得，使用三個 demo 字或手動釋義。P1 補上正式資料與多義字選擇。

1. 單字庫至少有名稱、目標語言、釋義語言；預留口音與目標保留率。
2. 語音有「唸單字」與「逐字母拼讀」兩種模式，使用者自行選擇。
3. 啟動辨識前說明可能使用線上服務；只在使用者點擊時啟用麥克風。
4. 顯示結果與候選字，讓使用者校正。不能辨識時保留原稿與文字輸入。
5. 拼字可能混淆 B/D/P、double u 等，P0 只處理明確字母序列；P1 提供候選確認，不自行猜完就存。
6. 字典先確認詞形、詞性、詞義、IPA、口音與可用錄音；找不到則標示缺漏。
7. 依已選詞義找例句與圖；故事可由 AI 原創，標示來源類型。
8. 預覽可修改所有文字、換圖、重試單一欄位、手動補充；必填為詞與已確認釋義。
9. 保存成功才清空，焦點回到輸入框；重複單字不清稿，提供開啟已存項目。
10. 同庫同正規化詞去重是 P0 規則；P1.1 改為 `deck + lemma + senseKey`，不同詞義需明確確認。

### 3.2 開始學習

```mermaid
flowchart LR
  A[選單字庫] --> B[取到期卡與新卡]
  B --> C[正面：先回想]
  C --> D[使用者揭示答案]
  D --> E[背面：釋義、聲音與語境]
  E --> F[忘了／困難／記得／熟記]
  F --> G[交易保存排程與複習紀錄]
  G --> B
```

採「先揭示、再評分」，讓評分基於是否真的答對。使用者原始描述的「先評分再顯示背面」可作為日後的信心預測實驗，但不能直接代替正誤回饋。

| 按鈕 | FSRS Rating | 給使用者的意思 |
| --- | --- | --- |
| 忘了 | Again = 1 | 想不起來，或答錯 |
| 困難 | Hard = 2 | 答對，但費力／猶豫 |
| 記得 | Good = 3 | 正常回想正確 |
| 熟記 | Easy = 4 | 立即、輕鬆答對 |

「不確定」不直接等同 Hard。若已忘記就應選 Again，避免把失敗回想當成成功。這與 [Anki 的 FSRS 使用說明](https://github.com/ankitects/anki/blob/main/docs-site/manual/deck-options.mdx) 一致。

P0 只取 `due <= serverNow`、每批最多 100 張，評分後重新查詢；未到期卡不提前顯示。若 Again 卡在一分鐘後才到期，本次可先完成其他卡並顯示下次時間，按「檢查到期單字」再取卡。P1 增加會話內等待／更新、每日限額與新卡／複習卡排序。

## 4. 排程策略

- 使用 `ts-fsrs` 5.4.2，集中在 `services/scheduler.ts`；不重寫記憶公式。
- 預設目標保留率 `0.9`，只是一項模型設定，不是成效保證。P1 可按單字庫設定。
- P0 停用 fuzz 以利穩定驗證，保留套件的學習／再學習預設；完整解析後參數隨每筆 log 保存。
- 每張卡保存完整 FSRS 狀態：due、stability、difficulty、reps、lapses、learning_steps、state、last_review，以及套件其他必要欄位。
- `review_logs` 保存評分、伺服器 UTC 時間、前後狀態、套件原始 log、版本與完整參數，提供稽核、撤銷與未來重算基礎。
- 冷啟動先用套件預設參數；參數最佳化留 P2，需要足夠個人歷史，不能用任意他人的參數冒充個人化。
- 所有資料時間採 ISO 8601 UTC 字串，前端按使用者本機時區顯示。P1 的每日限額依明確設定的 IANA 時區切日。
- 同筆評分有 `requestId`；重送相同卡、評分、版本回傳已保存結果。另一分頁送舊 `version` 回 409。
- 卡片更新與 log 寫入同一 SQLite 交易；任一步失敗都不能留下半筆評分。
- P1 展示四種預估間隔時需用同一份狀態、時間與設定，真正評分仍由 server 計算。

參考：[ts-fsrs 官方程式與使用方式](https://github.com/open-spaced-repetition/ts-fsrs/blob/main/packages/fsrs/README.md)。

## 5. 架構與資料邊界

採單一儲存庫、單一 package，避免基本骨架就引入多套建置系統。前端與 server 分資料夾，共用 Zod 契約。詳細技術決策見 [ARCHITECTURE.md](ARCHITECTURE.md)。

```mermaid
flowchart TD
  UI[React 本機介面] -->|同源 /api| API[Fastify API]
  UI --> SPEECH[可替換 SpeechInput]
  UI --> TTS[瀏覽器合成語音備援]
  API --> LIB[Library 服務]
  LIB --> FSRS[FSRS Adapter]
  LIB --> DB[(SQLite)]
  API --> CONTENT[ContentProvider]
  CONTENT --> DEMO[DemoProvider]
  CONTENT --> DICT[P1.1：DictionaryProvider]
```

目前資料：`decks → notes → cards → review_logs`，migration 獨立版本化。Note 保存學習內容；Card 保存一種測驗提示的排程；ReviewLog 保存不可隨意覆寫的學習事件。不要將這三者混為一份可任意覆寫的 JSON。

目前一 note 一 card；P1.1 已拆出 `senses`、`field_sources` 並保留 content JSON 快照。P1.2 將新增 `media_assets`、`generation_jobs`。P2 允許一 note 多種 card，維持各自的記憶狀態。詳見架構資料表。

## 6. 正式內容取得與生成

### 6.1 Provider 分工

| 介面 | 輸入 | 輸出與規則 |
| --- | --- | --- |
| SpeechInput | 語言、單字／拼讀模式、麥克風 | transcript、候選、可信度（若有）；不自行儲存 |
| DictionaryProvider | lemma、語言、口音 | 詞性、義項、IPA、字典來源、可用真人錄音與授權 |
| ExampleProvider | sense、程度 | 短例句、譯文、來源／作者／授權；查無時可轉原創 |
| ImageProvider | sense、詞性、情境 | 候選圖片、語意描述、作者、授權、來源；抽象字允許無圖 |
| LearningContentProvider | 已確認 sense、程度、母語 | 原創例句、搭配詞、小故事；標示模型與生成時間 |
| PronunciationProvider | lemma、口音 | 真人音檔優先；找不到才回明確的 TTS 備援 |
| ContentProvider | 輸入詞與設定 | 協調以上來源、回傳各欄位狀態與可校閱草稿 |

目前已實作 ContentProvider（demo 與字典草稿協調）及 DictionaryProvider（Free Dictionary API v2）。正式例句／圖片／原創內容與錄音播放 provider 留 P1.2。

### 6.2 來源選擇與品質

1. 優先用有文件與明確授權的 API／資料集，避免任意爬整個網頁。
2. 可先評估 Wiktionary 的結構化資料與 [Kaikki 官方資料](https://kaikki.org/) 作為字典來源；需另外驗證來源版本、資料授權、義項辨識與繁中翻譯品質。
3. 例句可評估 Tatoeba；導入前確認實際句子與音檔的授權，文字與音檔不要假設相同授權。
4. 圖片可評估 Wikimedia Commons API；每個檔案需記錄自己的來源、作者與授權，不能把整站當成同一授權。[官方重用說明](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en)。
5. 原創故事與搭配詞可用可設定的 LLM provider；目前不綁定廠牌、模型或付費方案。導入當下另查官方 API 文件、費率與資料處理條款。
6. 生成前固定詞性與義項，使用簡單自然的語句，預設 1–2 句例句、2–4 個常見片語、40–80 個英文單字的小故事。
7. 不由模型憑空產生權威 IPA 或聲稱錄音者是母語人士。這些欄位來自可驗證字典／錄音 metadata。
8. 每欄有 `pending / ready / missing / error`；部分失敗仍可編輯並儲存，缺漏欄位可稍後補。
9. 每欄保存 source kind、provider、原始連結、作者、授權連結、取得時間、模型／prompt 版本、人工修改旗標；不要用一個全域 source 代表多個來源。

### 6.3 工作生命週期與容錯

P0 預覽為不落盤的同步 demo；P1 真實內容用 SQLite 工作表與單程序 worker，不引入 Redis。

`queued → running → partial / completed / failed / cancelled`；每個欄位可獨立重試。重啟將超時的 running 工作回到 queued，已完成的欄位保留。

- key：正規化詞 + 語言 + sense + 口音 + 程度 + provider/model/promptVersion，人工修改內容不能被快取覆蓋。
- 字典／例句預設 10 秒，生成 30 秒，媒體 20 秒；最多 2 次退避重試，429 尊重 Retry-After。實際值可依供應商調整並測試。
- 工作生成可能收費；有預估／用量紀錄、超額提示，重試不悄悄產生重複任務。
- 使用者離開畫面不應遺失已輸入草稿；使用者取消才中斷，保存已回傳欄位。
- 供應商停用、無 key、離線時明確顯示原因並保留手動建卡路徑。

### 6.4 媒體儲存

P1 將核准使用的圖片／音檔下載到 `data/media/<sha256>.<ext>`，資料庫保存相對路徑、hash、MIME、大小、來源與授權。用本機 `/api/media/:id` 讀取，匯出時一併帶走，避免依賴失效遠端連結。

下載僅允許 provider 指定 HTTPS 網域；驗證重導向每一跳、不接受 loopback／私網／file URL，限制圖片 5 MB、音檔 10 MB、檔案類型與下載時間，避免未來 provider 變成任意網址讀取器。任意 HTML 不進前端，故事以純文字呈現。P0 的 asset 型別只是契約預留，介面未渲染外部素材、server 未下載媒體。

- 撤銷上一筆評分：僅允許無後續衝突的最後事件，交易還原狀態並保存撤銷事件；不直接刪除稽核紀錄。
- 前端持續使用相同 requestId 重試；有衝突可重新載入；會話進度在重新整理後可恢復。
- 統計以真實 logs 計算：今日完成量、到期數、Again 比率；不顯示虛構學習連續天數。
- 驗收：忘了會在相應學習間隔再現；雙分頁不雙重計分；午夜、夏令時間、數日後重開與撤銷皆有測試。

### P1.5：MVP 驗證與交付

依賴：P1.1–P1.4。

- 實際桌機 Chrome／Safari／Firefox 測文字建卡、權限拒絕、語音能力偵測與真人音檔；不支援語音也可完整使用。
- 自動化關鍵 UI 流程、provider contract、檔案完整性、migration／backup restore 與 `pnpm check`；CI 固定 Node 與 pnpm。
- 空資料、無網路、供應商失效、超過額度、媒體缺漏皆有可理解的 UI。
- 手動建立 20 個跨詞性單字，再以真實使用紀錄檢查學習流程，人工檢查詞義、IPA、例句與圖片相關性。
- 粗略衡量建卡操作次數、從辨識到保存的時間、人工修改比例、生成失敗率；數字是驗證結果，不預填成功率。

## 8. 測試策略與完成定義

| 範圍 | 需要覆蓋 |
| --- | --- |
| 共用契約 | 字詞正規化、字母序列、長度、語言、欄位缺漏與不安全 URL |
| 排程 | 四評分、重新學習、due 邊界、UTC 序列化、真實 FSRS 狀態保存 |
| 資料 | 去重、跨庫、migration 重跑、重啟保存、FK、交易回滾 |
| 複習請求 | 同 requestId 重試、同 id 不同內容、舊版本、提前評分 |
| Provider | 成功／空結果／多義／逾時／限流／格式錯誤／部分成功，不呼叫付費服務 |
| UI | 建庫、辨識修正、預覽編輯、保存連續輸入、揭示後評分、錯誤重試 |
| 本機資料保護 | 外站 Origin、Host 偽裝、輸入大小；未來媒體與匯入需額外驗證 |

每個里程碑完成需：實際功能、相關行為測試、可操作介面、文件與狀態更新、明確列出的未驗證項目。若必須付費憑證才能完成現場驗證，先完成 provider 與測試 fixture，指出所需設定；不能以假資料宣稱串接成功。
